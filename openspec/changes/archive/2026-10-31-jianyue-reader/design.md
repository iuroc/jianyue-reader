# Design

## Context

动机见 `proposal.md`。这里只记约束与由此推出的技术选择。

- 运行环境：iApp 5.0.1013，主开发机 API 34；界面按 mjava 建树范式构建（`.iyu` 只留根容器与事件表）。
- 内容源：歌德借阅机五个 GET 端点。**页码由分页参数决定**，同一本书换参数即换页数与目录页号。
- 服务端**没有搜索、没有推荐**；`keyword` 被静默忽略。
- 目录是**树**，深度上限未验证（样本 14 个都 ≤ 2 层），必须按递归处理。
- 正文是每页一段 HTML 片段，图片带写死的宽高属性。

## Goals / Non-Goals

**Goals:**

- 书库 / 期刊两条浏览链路各自完整，共用同一套网格与列表规范。
- 阅读器在几百页的书上也保持恒定内存：一次只持有一页。
- 所有网络等待都有可见、不抖动的状态表现。
- 索引建立可在后台推进，进程中断后不回退到零。

**Non-Goals:**

- 不做客户端重新分页（不切分服务端页、不做左右翻页手感）。
- 不做离线整本缓存、书签、笔记、朗读、账号同步。
- 不做跨设备进度同步。

## Decisions

### 决策 1：服务端页就是页面

阅读器一次只渲染 `contents[]` 里的一条，页码即 `catalogs[].page`。

- **为什么不拼接成长文档**：拼接会让内存随阅读线性增长，几百页的书需要 `content-visibility`、
  DOM 裁剪、滚动补偿一整套机制；而且每条内容的页号与视觉位置脱钩，进度只能按比例估算。
- **为什么不客户端分页**：需要按视口高度切分 HTML，图片页容易破版，字号/行距每次变化都要重算，
  复杂度远高于收益。
- **代价**：服务端按 1000×2000/18 切出的一页在手机视口下可能超出一屏，需要页内滚动。
  这是已知且可接受的，因为翻页规则（先滚到底再翻）已经兜住了内容丢失。

### 决策 2：正文按 30 页分组取回

`start(p) = floor((p-1)/30)*30 + 1`，一次取 30 页，缓存键为 `surl + 分页参数 + start`。

- 顺序阅读只在跨组边界时发请求；跳页只取目标所在组。
- 内存中按 LRU 保留少量组，退出阅读即释放。
- 为什么不逐页取：请求数放大 30 倍，且相邻页几乎总是紧接着被读。
- 为什么不是一次取全书：整本体积可达 1~3 MB，且多数阅读会中途离开。

### 决策 3：常驻底栏 + 按钮翻页

底栏 48dp + 系统栏内边距，含目录 / 上一页 / 页码 / 下一页 / 外观。

- 不绑定滑动手势：正文只有纵向滚动一种手势，避免与页内滚动冲突。
- 「下一页」在未滚到底时只执行滚动，到底后才翻页；「上一页」直接翻。
- 首页与末页对应按钮置灰。

### 决策 4：目录用 M3 模态抽屉 + 递归树

用 `DrawerLayout` 作为容器，内容按 M3 导航抽屉规格自绘。

- 宽度 320dp、仅 end 侧 16dp 圆角、遮罩 32%、活动指示器 12% 朱砂。
- 渲染前把**展开的**树拍平成一维行列表，展开状态用节点键记录；默认只展开顶层。
- 打开时递归求「当前页命中的最深节点」，展开其祖先链，先量高再定位，最后才播放滑入动画。
- 子项页码与直接父项比较：相同则不显示页码（页内小标题），不同则显示并作为独立跳转目标。
- 为什么不用独立页面：目录必须不打断阅读会话，压栈会让阅读页 pause 并在返回时重走生命周期。

### 决策 5：本地索引 + 内存子串匹配

馆藏约 4,000 本图书 + 495 种期刊，全量抓到本地后，搜索是内存子串匹配，毫秒级。

- **不需要倒排索引、不需要分词**：数据量小，子串匹配已足够。
- 按分类分 19 个分片，**4 线程并发**抓取，每片完成即落盘；合并后得到单文件索引。
- 并发度是常量，可降级到 2 或串行（skill 记录过 18 并发会导致大面积超时）。
- 断点续建：分片文件存在即视为完成，重启只补缺失片。
- 索引约 0.9 MB（只留书名 / 作者 / 封面短址 / 阅读入口 / 类型）。

### 决策 5b：书架格子随内容排布

书名与作者各自最多两行、超出省略，**不锁最小行数、不强制等高**，格子高度随内容伸缩。
曾尝试「标题固定两行 + 作者贴底」以求等高，实测发现两处代价：单行书名下方出现一整行空白；
且 `TextView` 的 `includeFontPadding` 会让真实高度比 `getLineHeight()` 多出一截，
骨架与真实布局对不齐。简单按顺序排布反而稳定。

配套的间距规则：**块内贴紧、块间分开**。书名两行之间用字体默认行距（不叠加倍率），
书名与作者之间留 8dp。注意 `setLineSpacing` 的倍率是叠乘在字体自身行高之上的，
手算 `字号 × 倍率` 会偏小，任何高度测量都走 `getLineHeight()` 实测。

### 决策 6：视觉用「宣纸编辑式」

```
角色        纸          夜
bg          #F7F4EE     #15140F
surface     #FFFDF8     #1E1C17
ink-1       #1C1A17     #E9E4D8
ink-2       #6B6459     #9A9384
hairline    #E4DED2     #2E2B25
accent      #A6402D     #C4634E
```

- 全 App 不用卡片，分组靠发丝线与留白；强调色只出现在进度、当前章节、目录焦点三处。
- 字号阶梯 28 / 20 / 17 / 13，字重 400 / 500；阅读器正文另有 15 / 17 / 20 三档。
- 图标统一 24dp 盒、1.5dp 线宽、圆头；只能 Canvas 现画（图片资源没有一条路径同时覆盖开发与打包）。
- 页头统一为工厂函数，间距与返回按钮位置在代码层面无法漂移。

### 决策 7：按压反馈统一为带形状遮罩的涟漪

三类控件三种遮罩：圆形按钮用 `OVAL`、pill 用同半径圆角、列表行与格子用直角。
第三参数传 `null` 会让涟漪扩散成整圆并溢出边界（既有实测结论），因此遮罩必须显式给。

### 决策 8：加载态三型

骨架（首屏）、扫动线（底部追加 / 打开书）、错误态（原位 + 重试）。
不使用转圈、不使用弹窗或 Toast。**「加载更多」区域高度恒定**，四种状态只换内容不换高度。

### 决策 9：WebView 只保留纵向滚动

关闭缩放、缩放控件、悬浮按钮、长按菜单、横向滚动、边缘拉伸；正文不可选中；
图片以 `max-width:100% !important; height:auto !important` 压回，不改写服务端 HTML。

### 模块划分

```
基础  ui（vendor，不改）  theme  icon
通用  widgets
共享  shelf（三列网格 + 固定高度加载槽）  cattabs（横向分类栏）
数据  net（接口 + 分组缓存）  store（进度 / 设置 / 索引状态）  indexer（索引构建）
页面  home  book  mag  mine  bookdetail  magdetail  reader  toc  search
```

依赖方向单向：页面 → 共享 → 通用 → 基础；数据层不依赖视图。

## Risks / Trade-offs

- **服务端页与手机屏不对齐** → 页内滚动兜底；若实测长年需要滚动，再评估调小分页参数
  （会成倍增加请求数，属最后手段）。
- **并发建索引的线程安全**：BeanShell 解释器不保证线程安全 → 共享状态只放原子量，
  每个线程持有局部变量与独立分片文件；上机探针验证。
- **并发限流未知**：4 并发是折中值，非实测阈值 → 常量可降级，实测超时即下调。
- **封面防盗链或慢** → 固定比例占位 + 书名首字失败态，网格不因单张失败而跳动。
- **`DrawerLayout` 尺寸约束**：必须使用精确尺寸，用 `match_parent` 会抛异常 →
  由 `DisplayMetrics` 计算宽高后显式设置。
- **索引体积与首建时长**：约 9 MB 下载、约 5~6 秒 → 进度可见 + 断点续建 + 后台继续。
- **目录深度未知**：按 4 层预留，超出后缩进封顶但内容不丢。

## Migration Plan

全新工程，无迁移。落地顺序：先探针确认关键未知，再骨架与规范，再内容，最后打磨。
回滚以 commit 为节点（单分支，不建分支模型）。

## Open Questions

- 目标机 WebView 内核版本是否支持所需的 CSS 特性（`!important` 覆盖内联属性、圆角裁剪）。
- 4 并发建索引在真实网络下的超时率。
- 大字号下每页平均需要滚动几次，用于判断分页参数是否需要调整。
